# 2026-09-28 資料流程與效能修正

## 現況核對

本輪開始時的公開快照 `a145a40` 有 105 款，與已接受的主清單 AppID 一致；其中 47 款缺正式大圖／語言資料，76 款沒有 TAG。這是已收錄內容的缺漏，不是已證明所有未來一年候選都完整收錄。

回填後 105 款都有正式封面、語言資料與 TAG，其中 103 款有 Steam 實際提供的 2x 圖片。AppID、Followers 數值、Followers 查詢時間、發售日期與最近一次公開基準一致。發布期間既有日期稽核另外修正了 3 款日期，本輪保留該較新結果。未提供 2x 的遊戲保留最佳既有圖片，不猜測資產網址。

## 各階段責任

| 階段 | 負責專案 | 完成依據 |
|---|---|---|
| 候選與資格 | `game-trend-radar-backend` | 日期、成人內容與官方 Followers 通過既有條件 |
| 接受紀錄 | 主後端 `steam_upcoming_master.json` | 官方數值與日期證據已保存 |
| 內容補充 | `game-trend-radar-content-backend` | 圖片、語言、TAG 已取得或明確記錄待重試 |
| 發布對帳 | 內容後端每日 07:30／19:30，Asia/Taipei；由 Cloudflare 觸發 | 主清單、單款檔、月份與列表一致；顯示實際待補數 |
| 網頁讀取 | 靜態前端 | 精簡清單成功；失敗才使用完整備援或月份分片 |

事件送出成功不等於遊戲已發布。對帳每輪由 12 款提高到最多 60 款，40 分鐘後不再啟動新工作；單款失敗延後 6 小時，其他遊戲繼續。429 會停止向 Steam 發送後續請求，但仍可修復本地索引。Cloudflare 觸發與 GitHub runner 開始執行仍可能延遲。

## 防止再次缺漏

- 以完整欄位比較公開紀錄，不只看 AppID、數量或是否有 header。
- 暫時取不到 TAG 時保留有效舊資料，空值與失敗分開記錄。
- 已上市的既有紀錄可以補內容，不要求不存在的未上市日期顯示，也不偽造重新查核日期。
- 同次 commit 更新單款、月份、精簡清單、完整備援與索引。
- 遇其他工作同時發布，重新讀取最新前端並合併成功紀錄；重試發布不重新抓 Steam。
- 空白／格式錯誤的權威來源不會觸發大批刪除；過期事件不能回滾較新 Followers；較新的日期稽核結果也不會被舊主清單或內容快取覆蓋。

## 尚未解決的覆蓋問題

現有官方 Followers 佇列主要處理尚未拿到數值的候選；已有官方數值的遊戲並未因此自動獲得每日／每三日的重查。之後需增加依到期時間安排的獨立更新佇列，與初次補漏共用限流狀態。第三方初篩低估、官方限流與尚未處理的候選仍可能延遲收錄。

本輪沒有清除原有 Followers 斷點、改動收錄門檻，或把補內容時間當成 Followers 更新時間。直播蒐集流程維持原狀。
